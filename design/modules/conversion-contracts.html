Skill Conversion Contract

Each source .claude/skills/<name>/SKILL.md produces one target skills/<name>/SKILL.md. The generated file must be concise enough for Codex skill loading and move large examples or catalogs into references.

Claude Field or Pattern Codex Target Rule
name name Keep kebab-case names unless a collision appears. Collisions fail conversion.
description description Rewrite to mention when Codex should use the skill. Include the old slash command as an alias phrase.
argument-hint Body section Invocation Inputs Preserve input shape as prose because Codex trigger metadata does not use this field for routing.
user-invocable Description wording Drop the field. If true, include the use case in the description.
allowed-tools Body constraints only when behaviorally necessary Remove Claude tool lists. Replace Task delegation instructions with Codex sub-agent guidance only where the current Codex environment allows it.
model Reference note, if needed Do not require a Codex model override. Mention high-complexity review only when the skill needs it.
Large workflow examples references/<topic>.md Move examples over 150 lines out of the main SKILL.md and link them from the relevant step.
Slash command references such as /design-system Skill name and alias text Use "the design-system skill" as the primary form. Keep slash syntax only in migration notes or source examples.

Role Conversion Contract

Each source agent prompt is preserved as role guidance, not as executable custom-agent metadata. Generated role references must keep domain authority, collaboration protocol, escalation paths, and file ownership constraints.

Claude Agent Field Codex Target Rule
name references/roles/<name>.md Keep the original name for traceability.
description Role summary and routing index Use it to decide when a skill should consult the role reference.
tools, disallowedTools Safety notes only Remove Claude tool names. Preserve intent such as "does not run shell commands" when it is a domain boundary.
model, maxTurns, memory Source metadata table Record for traceability. Do not make it a Codex runtime requirement.
skills Role routing index Map to target Codex skill names and flag missing skills as conversion errors.

CLAUDE.md AGENTS.md Inline core collaboration and project-structure instructions. Replace @path includes with readable links or summaries.
src/CLAUDE.md, docs/CLAUDE.md, design/CLAUDE.md Path-specific AGENTS.md files when the port creates those directories Preserve path scope. Do not put Codex-only files under .trae or source .claude.
.claude/rules/*.md references/rules/*.md and root routing summary Keep detailed rules as references and expose when to read each one.

Hook and Script Contract

Hook scripts move through two states. State 1 is required for the initial port; State 2 is allowed only after schema verification.

State Output Pass Condition
State 1: script preservation scripts/hooks/*.sh plus references/hooks.md Scripts are copied with executable bit preserved where supported, shellcheck-safe changes documented, and no automatic event binding generated.
State 2: Codex hook registration hooks.json and manifest hooks field Codex hook event names, input schema, timeout behavior, and failure semantics are verified against current Codex documentation or local examples.
